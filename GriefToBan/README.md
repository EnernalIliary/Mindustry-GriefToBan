# Grief to Ban

基于 uid 的反破坏模组（纯 JS + Rhino，无 Java 代码）。

## 它做什么

- **黑名单（uid）**：名单里的玩家进服直接被切成旁观（队伍 0），不再能操作。
- **移出黑名单**只有两条路：把对方设成管理员（下次 tick 自动移出），或在设置页里手动移出。
- **游戏默认黑名单**：打开后同时写入 Mindustry 自己的封禁列表（`banPlayerID`）。
- **语言黑名单**：按 `player.locale` 匹配，命中就拉黑；或只「列为观察对象」。
  选了观察对象时，下面所有「成员」只指观察名单里的人。
- **行为黑名单**（六项，可逐项开关）：
  1. 短时间多次交互 / 指挥大量单位 —— 拉黑 + 通告；
  2. 放置病毒逻辑（`ucontrol build … @this` 自复制）—— 停用该逻辑 + 拉黑 + 通告；
  3. 钍堆离核心过近（默认 30 格）—— 警告 + 通告；
  4. 钍堆热量不为 0（随时会炸）—— 停用该钍堆直到热量归零 + 拉黑 + 通告；
  5. 给涡轮 / 火电装爆混 —— 清空并停用该发电机 + 警告 + 通告；
  6. 附身单位 AFK（`@shootx @shooty` 不动，默认 3 分钟）—— 踢出 + 通告。
- **/vote kick 期间自动旁观**：有人发起投票时把目标转为队伍 0，投票结束自动恢复原队伍。
- **维护**：在 GitHub 上检查更新（仓库地址可在设置里改），失败只提示不报错。

## 设置

游戏内 `设置 → Grief to Ban`（锤子图标），排版与 Mlog辅助 一致：
主体色 / 强调色可配，另外可在线管理黑名单与观察名单（把在线玩家加进去 / 移出来）。

## 文件

- `scripts/main.js` —— 事件绑定、处置逻辑、设置页 api
- `scripts/gtb-lib.js` —— 纯逻辑（名单、语言、计数窗、文案），可被 Node 直接测试
- `scripts/gtb-ui.js` —— 设置界面
- `tests/grief-to-ban/` —— Node 纯逻辑测试 + 服务器加载探针

## 限制

- 无 Java、无内容注册，因此 `hidden: true`。
- 「指挥大量单位」本版没有专门事件，按 建造/配置/控单位/指挥方块 的事件计数近似。
- 停用方块走 `enabled` 字段（包私有，反射兜底），失败时钍堆退化为 `heat = 0`。
